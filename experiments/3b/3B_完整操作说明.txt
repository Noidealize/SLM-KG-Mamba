九、显存和异常处理

1. 必须保留 --no_use_amp；本机 3B fp16 前向曾产生 NaN。
2. 默认 batch_size=8。若 CUDA out of memory 或整机冻死，改为 4；不要先提高到 16/32。
3. train_smetimes.py 已内置四套本机实测防护（详见文件头注释）：
   - eager attention（patch_eager）：修 RTX 5070 Ti 上 sdpa 内核的非确定性 NaN；
   - 前向 NaN 检测重试（NaN-guard）：坏样本替换后重跑；
   - Hybrid-Adam + CPU 裁判：≥4MB 参数（experts.0.weight）走 CPU 权威路径
     （GPU 大张量 elementwise 内核会以 ~5% 概率产出坏值）；小参数 GPU 原地
     更新，但每步由 CPU 用同一份清洗后梯度复算比对（阈值 1e-3），不一致
     即 GPU 静默损坏、用 CPU 权威值写回修复；同步点 ~10/步（全量 CPU-Adam
     为 40+，本机冻机原因）；CPU 侧限 2 线程；
   - 冻结权重完整性校验：模型构造时记录冻结 Llama 权重的参考哈希（fp64），
     每 2000 步与每次验证/测试前重算比对，不一致重算一次仍坏则立即中止
     训练（日志出现 INTEGRITY FAILURE = 权重被静默改坏，该次检查点与
     result 文件作废，需重新训练）。
4. 所有 python 命令必须带 -u 且先设置 $env:PYTHONUNBUFFERED='1'：
   stdout 走 PowerShell 管道时是 8KB 块缓冲，进程异常退出会丢失缓冲内的
   全部 print（日志看起来"停在某处"，实际进程已跑远）。同时设置
   $env:PYTHONFAULTHANDLER='1'，原生崩溃会打印 Python 栈帧到日志。
5. 若日志反复出现 guard exhausted 或训练损失为 NaN，应停止该次训练并保留
   日志，不要把该检查点作为有效结果。
6. 冻机预案（2026-08-30 曾在 epoch 3 冻死整机）：根因是全量 CPU-Adam 打满
   CPU + 后台应用挤占显存，已通过 Hybrid-Adam + 限线程修复；若再次冻机，
   重启后按顺序排查：nvidia-smi 确认显存 → batch_size 8 改 4 → 保留日志。

十、运行记录

2026-08-30：
  1. 首次训练无输出地停止：进程实际进入了训练循环，但 stdout 管道块缓冲
     吞掉了所有 print，进程死亡时缓冲丢失，日志停在"Loading weights"。
     修复：全部命令加 -u + PYTHONUNBUFFERED，此后日志实时落盘。
  2. 带诊断重跑后训练正常（0.137-0.142 s/iter），但到 epoch 3 iter 6000+
     整机冻死：全量 CPU-Adam 每步 40+ 次 GPU 同步 + 多线程 CPU 运算打满
     全部核心，GPU 利用率低。修复：Hybrid-Adam（大参数 CPU 权威路径不变，
     小参数 GPU 更新）+ OMP/MKL 限 2 线程；test_hybrid_step.py 验证通过。
  3. Hybrid-Adam 下首次完整训练（5 epochs，早停）跑完但结果作废：epoch 3
     最后 89 个 batch 内 loss 从 0.65 骤升 2 万+（train 204），epoch 4-5 每步
     ~5/8 参数梯度爆炸被跳过、模型冻结在 train ~220K。全程零 NaN、零读回
     坏值告警——崩溃由"有限坏值"静默写坏权重导致（isnan 拦不住的已知
     故障形态），当时的盲区是小参数无权威校验 + 冻结权重从未校验。
     修复：小参数 CPU 裁判（每步复算比对+权威值修复）+ 冻结权重哈希校验
     （每 2000 步与验证前，坏则中止）；test_hybrid_step.py 全部用例通过
     （含 NaN 梯度裁判连续同步、坏值修复、中止路径的回归测试）。
     该次报告的 mse 0.3976 / mae 0.4254 来自崩溃前的 epoch-2 检查点，只代表
     2 轮训练水平，不可作为 3B 最终成绩。
